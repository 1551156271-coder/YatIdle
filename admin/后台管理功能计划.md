# YatIdle 后台管理功能计划

## 1. 目标

在现有 `YatIdle` 项目中新增一个独立的 uni-app H5 后台管理端，放在：

```text
C:\Users\Raymond\Desktop\新建文件夹\YatIdle\admin
```

后台管理端主要给管理员在电脑浏览器中使用，用来管理校园二手交易平台的用户、商品、求购、订单、举报、评价、聊天记录和分类配置。

技术方向：

- 前端：独立 uni-app H5 项目，目录为 `admin/`
- 后端：继续使用现有 Spring Boot 后端，在 `backend` 中新增 `/api/admin/**` 管理接口
- 数据库：继续使用现有 MySQL `yatidle` 数据库，补充举报表和管理员操作日志表
- 权限：使用现有 `user.role` 字段，`0=普通用户`，`1=管理员`

## 1.1 Git 分支要求

后台管理功能必须在独立分支上开发，不允许直接在 `main` 分支或当前默认分支上修改。

新会话开始实现前，先执行：

```bash
git status
git switch -c admin
```

如果本地已经存在 `admin` 分支，则执行：

```bash
git switch admin
```

开发要求：

- 所有后台管理相关代码都提交到 `admin` 分支
- 不要在 `main` 分支直接修改代码
- 如果当前工作区有未提交修改，先确认这些修改是否属于后台管理功能
- 每完成一个阶段建议提交一次 commit
- 后续需要合并时，再从 `admin` 分支发起合并或 Pull Request

## 2. 后台第一版功能范围

本项目按“完整运营版”规划，但实现时建议分阶段完成。

### 2.1 首页数据看板

后台首页展示平台整体状态：

- 用户总数
- 今日新增用户数
- 商品总数
- 在售商品数
- 求购总数
- 订单总数
- 待处理举报数
- 成交订单数
- 近 7 天发布趋势
- 近 7 天订单趋势

建议接口：

```text
GET /api/admin/stats/overview
```

### 2.2 管理员登录

后台单独提供管理员登录页。

要求：

- 只允许 `role=1` 的用户登录后台
- 用户 `status` 必须是 `active`
- 登录成功后保存 `adminToken` 和 `adminUser`
- 普通用户登录后台时提示“无管理员权限”

建议接口：

```text
POST /api/admin/auth/login
```

请求：

```json
{
  "username": "admin",
  "password": "123456"
}
```

返回：

```json
{
  "token": "jwt-token",
  "user": {
    "id": 1,
    "username": "admin",
    "role": 1,
    "status": "active"
  }
}
```

### 2.3 用户管理

后台可以查看、搜索、封禁和解封用户。

功能：

- 用户列表分页
- 按用户名搜索
- 按状态筛选：正常、封禁
- 按角色筛选：普通用户、管理员
- 查看用户详情
- 封禁用户
- 解封用户
- 设置用户为管理员
- 取消管理员权限

建议接口：

```text
GET /api/admin/users
GET /api/admin/users/{id}
PUT /api/admin/users/{id}/status
PUT /api/admin/users/{id}/role
```

状态修改请求：

```json
{
  "status": "inactive",
  "reason": "违规发布虚假商品"
}
```

角色修改请求：

```json
{
  "role": 1
}
```

### 2.4 商品管理

后台可以管理所有商品。

功能：

- 商品列表分页
- 按标题搜索
- 按分类筛选
- 按状态筛选：在售、已售、已下架
- 按校区筛选
- 查看商品详情和图片
- 管理员强制下架商品
- 恢复被下架商品
- 删除违规商品

建议接口：

```text
GET /api/admin/items
GET /api/admin/items/{id}
PUT /api/admin/items/{id}/status
DELETE /api/admin/items/{id}
```

状态修改请求：

```json
{
  "status": "REMOVED",

}
```

### 2.7 举报管理

建议新增表：`report`

建议接口：

## 3. 数据库设计建议

### 3.1 report 表

```sql
CREATE TABLE IF NOT EXISTS report (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  reporter_id BIGINT NOT NULL COMMENT '举报人ID',
  target_user_id BIGINT DEFAULT NULL COMMENT '被举报用户ID',
  item_id BIGINT DEFAULT NULL COMMENT '关联商品ID',
  wanted_id BIGINT DEFAULT NULL COMMENT '关联求购ID',
  order_id BIGINT DEFAULT NULL COMMENT '关联订单ID',
  chat_session_id BIGINT DEFAULT NULL COMMENT '关联聊天会话ID',
  reason VARCHAR(50) NOT NULL COMMENT '举报原因',
  description VARCHAR(500) DEFAULT NULL COMMENT '详细描述',
  image_urls TEXT DEFAULT NULL COMMENT '截图URL，JSON数组字符串',
  status VARCHAR(20) NOT NULL DEFAULT 'PENDING' COMMENT 'PENDING/HANDLED/REJECTED',
  handle_result VARCHAR(500) DEFAULT NULL COMMENT '处理结果',
  handler_id BIGINT DEFAULT NULL COMMENT '处理管理员ID',
  handle_time DATETIME DEFAULT NULL COMMENT '处理时间',
  create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  update_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  is_deleted TINYINT NOT NULL DEFAULT 0,
  INDEX idx_report_status (status),
  INDEX idx_report_reporter_id (reporter_id),
  INDEX idx_report_target_user_id (target_user_id),
  INDEX idx_report_create_time (create_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='举报表';
```

### 3.2 admin_action_log 表

```sql
CREATE TABLE IF NOT EXISTS admin_action_log (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  admin_id BIGINT NOT NULL COMMENT '管理员ID',
  action VARCHAR(50) NOT NULL COMMENT '操作类型',
  target_type VARCHAR(50) NOT NULL COMMENT '目标类型',
  target_id BIGINT NOT NULL COMMENT '目标ID',
  before_status VARCHAR(50) DEFAULT NULL COMMENT '操作前状态',
  after_status VARCHAR(50) DEFAULT NULL COMMENT '操作后状态',
  remark VARCHAR(500) DEFAULT NULL COMMENT '备注',
  create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_admin_log_admin_id (admin_id),
  INDEX idx_admin_log_target (target_type, target_id),
  INDEX idx_admin_log_create_time (create_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='管理员操作日志表';
```

## 7. 测试计划

### 7.1 后端测试

- 普通用户不能登录后台
- 管理员可以登录后台
- 无 token 访问 `/api/admin/**` 被拒绝
- 普通用户 token 访问 `/api/admin/**` 被拒绝
- 管理员封禁用户后，用户状态变为 `inactive`
- 管理员下架商品后，用户端首页不再显示该商品
- 管理员处理举报后，举报状态变为 `HANDLED`
- 管理员删除评价后，用户端不再显示该评价
- 聊天审计接口只能读取，不能发送消息
- 所有关键操作都写入 `admin_action_log`

### 7.2 前端测试

- 未登录访问后台页面自动跳转登录页
- 普通用户登录后台显示无权限
- 管理员登录成功后进入首页
- 表格分页、搜索、筛选正常
- 封禁、下架、删除等危险操作都有二次确认
- 接口报错时页面显示明确提示
- 刷新页面后后台登录态仍然有效

HBuilderX/H5 注意事项：

- 后台端运行在浏览器 H5，不要使用小程序 `tabBar`。
- uni-app H5 会把 `view/input/button/text` 渲染为 `uni-view/uni-input/uni-button/uni-text`，写 CSS 时必须同时考虑这些 H5 宿主元素。
- 不建议在后台桌面端使用 `picker` 做筛选，下拉在 H5 上容易表现不稳定；优先用分段按钮、普通输入框、弹窗或自定义下拉。
- 页面表格要设置 `overflow-x: auto`、稳定列宽、文本省略，避免窄屏错位。

### 14.3 第二阶段：补 admin 专用 VO，提升后台可读性

当前后台很多地方还显示 `userId`、`itemId`、`orderId`，运营使用不直观。下一轮优先在后端新增 admin 专用 VO/DTO/service 方法，避免把复杂拼装放到前端。

建议新增或完善：

- `AdminUserVO`
  - 用户 id、用户名、昵称、手机号、校区、角色、状态、信用分、商品数、求购数、订单数、举报相关统计。
- `AdminItemVO`
  - 商品 id、标题、卖家用户名、分类名、校区、价格、状态、封面图、浏览数、收藏数、发布时间。
- `AdminReportVO`
  - 举报 id、举报人用户名、被举报用户用户名、原因、状态、关联商品标题、关联求购标题、关联订单号、处理人、处理时间。
- `AdminOrderVO`
  - 订单 id、订单号、商品标题、买家用户名、卖家用户名、金额、状态、交易地点、取消原因、创建时间。
- `AdminReviewVO`
  - 评价 id、订单号、评价人用户名、被评价人用户名、评分、内容、创建时间。
- `AdminChatSessionVO`
  - 会话 id、买家用户名、卖家用户名、商品标题/求购标题、最后消息、最后消息时间、未读数。
- `AdminActionLogVO`
  - 管理员用户名、操作中文名、目标对象名称、操作前后状态中文说明、原因、时间。

后端实现原则：

- 使用 service 层批量查询关联对象，避免循环里反复查数据库过多。
- controller 返回 VO，不直接返回实体给 admin 前端。
- 保持用户端原有接口不变，不破坏 `frontend`。

前端改造重点：

- 用户、商品、举报、订单、日志页面优先使用 VO 字段显示中文业务信息。
- ID 保留为辅助信息，例如 `#12`，但不要作为主要展示内容。

### 18.2 当前代码观察与初步根因判断

- `admin/pages/items/items.vue` 和 `admin/pages/users/users.vue` 的危险操作都使用了相同模式：
  1. 自定义 `modal-mask` 弹窗中填写原因。

  3. 再调用 `uni.showModal` 做二次确认。
  4. 用户确认后才设置 `submitting = true` 并发请求。
- 这个模式在 uni-app H5 中不可靠：自定义弹窗里再叠加 `uni.showModal`，容易出现遮罩层级、焦点、滚动容器和按钮事件冲突，最终表现为“点击了但没反应”。
- 上一轮已把删除接口从 `DELETE + body` 改成 `PUT /delete`，并验证后端接口本身可用；因此下一轮重点不是重建数据库，而是改前端交互提交链路。
- 图片比例问题主要来自当前统一样式：
  - 列表图使用固定 `56px * 42px` 加 `mode="aspectFill"`，会裁切。
  - 详情和操作弹窗使用 `.image-list` 横向/换行布局加 `.preview-img { width:112px; height:112px; object-fit: cover; }`，但 H5 渲染出的实际图片区域仍会被弹窗滚动和原图比例影响。
