# 浏览器 H5 体验与网络连接维护计划

日期：2026-06-11

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让软件端 `frontend` 在电脑浏览器和手机浏览器 H5 调试时都能稳定连接本机后端与数据库，并顺手提升移动浏览器下的用户体验和错误提示。

**Architecture:** 先把前端所有接口、上传、图片 URL 统一收口到同一个运行时 API 配置模块；H5 调试时根据当前访问页面的局域网 IP 自动推导后端地址，避免手机请求 `127.0.0.1`。后端补充局域网调试配置说明和必要 CORS/静态资源策略，前端补充网络诊断 UI、空状态、加载状态和移动浏览器适配。

**Tech Stack:** uni-app / Vue 3 / Vite / HBuilderX H5 dev server / Spring Boot / MySQL / Maven。

## 一、问题背景与根因判断

### 现象

HBuilderX/Vite 输出了多个访问地址：

```text
Local:   http://localhost:5173/
Network: http://172.17.192.1:5173/
Network: http://172.18.156.250:5173/
Network: http://192.168.200.1:5173/
Network: http://192.168.152.1:5173/
Network: http://172.26.10.154:5173/
```

手机浏览器里只有：

```text
http://172.18.156.250:5173/
```

能打开前端页面，其他地址一片空白或加载失败。打开后首页分类能看到，但数据库商品内容为空，并出现：

```text
网络请求失败
```

### 根因判断

1. `172.17.*`、`192.168.200.*`、`192.168.152.*`、`172.26.*` 很可能是 Docker、WSL、虚拟网卡、VPN、热点或其他虚拟适配器地址，不一定能被手机所在 Wi-Fi 访问。
2. `172.18.156.250` 大概率是电脑和手机同一局域网下可达的真实网卡 IP，所以只有这个前端地址能打开。
3. 前端能打开不代表后端可达。当前 `frontend/api` 里仍有多处硬编码：

```js
http://127.0.0.1:8080
```

手机访问 H5 页面时，`127.0.0.1` 指的是手机自己，不是运行 Spring Boot 的电脑，所以手机端请求数据库接口必然失败。

4. 即使普通接口改好了，图片上传和图片显示仍可能失败，因为上传接口和后端返回的图片 URL 也可能带 `127.0.0.1` 或 `localhost`。
5. 后端如果只监听本机、Windows 防火墙拦截 8080、或者图片资源返回了本机地址，也会导致手机浏览器无法获取数据库内容或图片。

function getH5RuntimeApiBaseUrl() {
  // #ifdef H5
  if (typeof window !== 'undefined' && window.location && window.location.hostname) {
    const protocol = window.location.protocol === 'https:' ? 'https:' : 'http:'
    const hostname = window.location.hostname
    return `${protocol}//${hostname}:8080`

- [ ] **Step 2：增强图片地址解析**

替换 `resolveImageUrl(url)`：

```js
export function resolveImageUrl(url) {
  if (!url) return ''
  const text = String(url)
  if (text.startsWith('http://127.0.0.1:8080')) {
    return text.replace('http://127.0.0.1:8080', BASE_URL)
  }
  if (text.startsWith('http://localhost:8080')) {
    return text.replace('http://localhost:8080', BASE_URL)
  }
  if (text.startsWith('https://') || text.startsWith('http://')) return text
  if (text.startsWith('/')) return BASE_URL + text
  return BASE_URL + '/' + text
}
```

在 `WebConfig.java` 增加：

```java
@Override
public void addCorsMappings(CorsRegistry registry) {
    registry.addMapping("/**")
            .allowedOriginPatterns("*")
            .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
            .allowedHeaders("*")
            .allowCredentials(false)
            .maxAge(3600);
}
```

同时增加 import：

```java
import org.springframework.web.servlet.config.annotation.CorsRegistry;
```

说明：

- 本项目登录 token 走请求头，不依赖 Cookie，所以 `allowCredentials(false)` 更适合开发期。
- 如果后续要做正式公网部署，再把 `allowedOriginPatterns("*")` 收紧为正式域名。
